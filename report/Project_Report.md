## Abstract

Packaged integrated circuits (ICs) are inspected visually before shipment for cracks, scratches,
contamination, chipped mould compound and missing leads. This project builds an automatic inspection
system: a top camera image of a conveyor is analysed by a **YOLO11** detector that finds every IC, a
**segmentation model** (YOLO11-seg or U-Net) that outlines each defect, a measurement step that converts
defect masks to millimetres, and configurable quality rules that decide **PASS, REWORK or SCRAP**.
Results are served through a **FastAPI** backend, shown on a **Streamlit** dashboard and stored in
**SQLite**. On 150 held-out test frames (307 devices) the selected pipeline
(YOLO11n + YOLO11n-seg) reaches a decision accuracy of **0.951** (macro F1
0.940) at 159 ms per frame on a CPU; the detector reaches
box mAP50 0.995.

## 1. Introduction

In semiconductor back-end manufacturing, every packaged device is inspected before it is taped and
shipped. Manual inspection under a microscope is slow, tiring and inconsistent. Automated optical
inspection (AOI) with deep learning can inspect every device in real time, measure defects objectively
and route each part to the right next step: ship it, repair it, or scrap it.

## 2. Problem Statement

Given a camera image of a conveyor or tray carrying IC packages, the system must
(1) locate every device, (2) find and outline every defect on it, (3) measure each defect, and
(4) decide whether the device should **PASS** (no significant defect), go to **REWORK** (minor, repairable
defect) or be **SCRAPPED** (major defect).

## 3. Objectives

1. Generate a labelled image dataset with exact boxes, masks and measurements.
2. Train a YOLO11 object detector for IC devices.
3. Train and compare two defect segmentation models: YOLO11-seg (instance) and U-Net (semantic).
4. Convert masks to physical measurements and apply editable quality rules.
5. Evaluate detection, segmentation and the final PASS/REWORK/SCRAP decision on unseen data.
6. Deliver a usable system: CLI, camera/video mode, REST API, dashboard and database.

## 4. System Architecture

```
Camera / image ──► OpenCV ──► YOLO11n detector ──► device boxes
                                   │
                                   ▼  square crop (8 % padding, 256 × 256)
                     YOLO11n-seg  or  U-Net  ──► defect masks (5 classes)
                                   │
                                   ▼  pixels → mm  (12 px/mm calibration)
                     area (mm²), length (mm) per defect
                                   │
                                   ▼  configs/quality_rules.yaml
                     PASS / REWORK / SCRAP per defect → worst = device decision
                                   │
             ┌─────────────────────┼─────────────────────┐
             ▼                     ▼                     ▼
       FastAPI backend      Streamlit dashboard     SQLite database
```

## 5. Dataset

Real labelled IC-inspection images with pixel masks are not publicly available, so a **synthetic image
generator** was written (`src/qc/synth.py`). It renders top-down camera frames of QFP-style IC packages:
dark mould-compound body with texture, marking text and pin-1 dimple, and silver leads on four sides,
placed at random positions and angles on one of four conveyor/tray backgrounds, with drop shadows, uneven
lighting, vignetting, colour cast, sensor noise and slight defocus. Because the generator draws each
defect itself, it outputs **exact** boxes, pixel masks and measurements.

| Property | Value |
|---|---|
| Camera frames | 750 (train: 500, val: 100, test: 150) |
| IC devices | 1459 (1–3 per frame) |
| Frame size / calibration | 512 × 512 px, 12 px/mm (field of view 42.7 mm) |
| Device sizes | 7–12 mm body, 1.0–1.4 mm leads |
| Defect instances | crack: 161, scratch: 514, contamination: 521, chip: 152, missing_pin: 152 |
| Ground-truth decisions | PASS: 611 (41.9 %), REWORK: 254 (17.4 %), SCRAP: 594 (40.7 %) |

Defect types: **crack** (dark jagged line with branches), **scratch** (thin bright line), **contamination**
(residue, flux or particle blob), **chip** (piece of mould compound broken off an edge or corner) and
**missing_pin** (one or two absent leads). About 12 % of devices carry only a *cosmetic* defect below the
rule limits, so the system must measure defect size, not just detect presence.

Splits are made per camera frame with separate random seeds; device crops inherit the split of their
frame, so no device appears in more than one split.

## 7. Methodology

### 7.1 Device detection — YOLO11n
Ultralytics YOLO11n (2.6 M parameters) initialised from COCO-pretrained weights and fine-tuned on the
frames (416 px input, 1 class `ic_device`). Default YOLO augmentation (mosaic, HSV, flips,
scale/translate).

### 7.2 Defect segmentation — YOLO11n-seg
YOLO11n-seg initialised from COCO-pretrained weights, trained on 256 × 256 device crops with polygon
labels for the 5 defect classes (instance segmentation: each defect gets its own mask, class and
confidence). Training crops are randomly shifted/scaled by a few percent to imitate detector box errors.

### 7.3 Second training stage for YOLO11n-seg (more effective training)
The first run stopped after 25 epochs while the validation mask mAP was still rising, and the weakest
classes were the thin and small ones (scratch, missing pin). Instead of restarting from COCO weights, a
second stage (`python run_project.py finetune-yoloseg`) **warm-starts from the stage-1 model** and:

1. **oversamples** training crops that contain a scratch (×3) or a missing pin (×2), so the rare, hard
   classes are seen more often (class balancing through a repeated image list);
2. uses a **lower learning rate with cosine decay** (AdamW, lr 0.002 → 0.0001, 1 warm-up epoch), the usual
   recipe for refining a converged model rather than relearning it;
3. adds vertical flips and ±15° rotations, halves mosaic and **switches mosaic off for the last 8 epochs**,
   so the final epochs see whole, realistic crops.

The stage-2 model replaces stage 1 **only if** the decision macro F1 on the **validation** split
(with re-tuned thresholds) improves; the test split is still used once, for the comparison in 9.6.

### 7.4 Defect segmentation — U-Net
A U-Net (4 down-sampling levels, base width 16, BatchNorm) written in PyTorch, predicting
a 6-class map (background + 5 defects). Loss: class-weighted cross-entropy + soft Dice (background is
~99 % of pixels). To make CPU training feasible it is trained on 128 × 128 patches (70 % centred on a
defect) and applied fully-convolutionally to the 256 × 256 crops; connected components of each class
become individual defects.

### 7.5 Measurement
For every defect mask: area = pixels × (camera px per crop px)² / (12 px/mm)²; length = long side of the
minimum-area rotated rectangle. Defects whose mask lies mostly outside the device box (a neighbouring
device inside the padded crop) are discarded.

### 7.6 Post-processing thresholds (tuned on the validation split)
Both segmenters use the same post-processing: a predicted defect is kept only if its confidence (YOLO
score, or mean U-Net class probability over the component) and its size (crop pixels) reach a
threshold. These two values were chosen per model by a grid search (confidence 0.1–0.9, minimum size
6–250 px) that maximises decision macro F1 on the **validation** split; the test split was used
only once, afterwards.

| Segmenter | Confidence ≥ | Min. size (px) | Val. macro F1 (tuned) | Val. macro F1 (default 0.2 / 6 px) |
|---|---|---|---|---|
| YOLO11n-seg | 0.1 | 6 | 0.882 | 0.841 |
| U-Net | 0.6 | 100 | 0.812 | 0.426 |

### 7.7 Quality rules (`configs/quality_rules.yaml`)

| Defect | Condition | Verdict | Reason |
|---|---|---|---|
| crack | any size | **SCRAP** | crack in package body |
| missing_pin | any size | **SCRAP** | missing lead |
| chip | area_mm2 < 0.5 | **PASS** | chip within cosmetic tolerance |
| chip | area_mm2 ≥ 0.5 | **SCRAP** | edge chipping too large |
| scratch | length_mm < 1.5 | **PASS** | scratch within cosmetic tolerance |
| scratch | 1.5 ≤ length_mm < 4 | **REWORK** | scratch - buff and re-mark |
| scratch | length_mm ≥ 4 | **SCRAP** | long scratch |
| contamination | area_mm2 < 0.5 | **PASS** | contamination within tolerance |
| contamination | 0.5 ≤ area_mm2 < 3 | **REWORK** | contamination - clean device |
| contamination | area_mm2 ≥ 3 | **SCRAP** | heavy contamination |

The device decision is the most severe verdict of its defects; a device with no defects passes.
The same rules applied to the exact ground-truth masks give the ground-truth decision.

## 12. Validation on Real Images (MVTec AD — transistor)

To check the approach beyond synthetic data, the system was tested on **real photographs** from the public
**MVTec AD** dataset (Bergmann et al., CVPR 2019), category *transistor*: through-hole transistors
photographed from above, with pixel-accurate masks for four real defect types — **bent lead, cut lead,
damaged case, misplaced** (transistor shifted, rotated or missing).

| Split | Images |
|---|---|
| Defect-free training images (MVTec `train/good`) | 213 |
| MVTec test images (60 good + 40 defective, 10 per type) | 100 |
| — calibration split (threshold choice only) | 40 |
| — held-out split (reported results) | 60 |

### 12.1 Anomaly detection without defect labels (PatchCore)
PatchCore (Roth et al., CVPR 2022) stores the mid-level features of every patch of the **defect-free**
images (ImageNet-pretrained YOLO11s-cls backbone, stride-8 + stride-16 features, 1 % greedy coreset);
a test patch far from all stored patches is anomalous. This mirrors a real factory, where good parts are
plentiful and defects are rare and unlabelled.

| Metric | Value |
|---|---|
| Image AUROC (all 100 test images) | **0.948** |
| Image AUROC (held-out 60) | 0.922 |
| Pixel AUROC (defect localisation, all test images) | 0.842 |
| Held-out accuracy (good vs defective, threshold from calibration split) | **85.0 %** |
| Held-out defect recall | 83.3 % (4 escapes) |
| Held-out false-reject rate (good parts flagged) | 13.9 % |

Recall per defect type (held-out): bent lead 100.0 %, cut lead 66.7 %, damaged case 83.3 %, misplaced 83.3 %.

![PatchCore heat-maps on real transistors](../results/graphs/real_patchcore_heatmaps.png)


### 12.2 Defect type with supervised YOLO11-seg (5-fold cross-validation)
MVTec provides only 40 defective transistor images, so YOLO11n-seg (384 px) was trained with
**stratified 5-fold cross-validation**: each image is predicted by a model that never saw it
("out-of-fold"). 60 defect-free training images are added to every fold as negatives. Two starting
points were compared — the model pretrained on **our synthetic IC data** (transfer from simulation to
real) and the generic **COCO** model.

### 12.3 Combined real-image inspection
PatchCore decides *defect or not*; if a defect is found, the type predicted by YOLO11-seg chooses the
verdict (`configs/transistor_rules.yaml`: bent lead / misplaced → REWORK, cut lead / damaged case →
SCRAP). Ground truth: good → PASS, and the same mapping for the defect types.

| Model | Mask mAP50 (5 folds) | Defect-type accuracy | Combined PASS/REWORK/SCRAP accuracy (held-out) | Macro F1 |
|---|---|---|---|---|
| YOLO11n-seg pretrained on our synthetic IC data | 0.414 ± 0.164 | 37.5 % | 73.3 % | 0.642 |
| YOLO11n-seg pretrained on COCO (generic) | 0.590 ± 0.088 | 70.0 % | 76.7 % | 0.707 |

Confusion matrix of the combined system with the pretrained on COCO (generic) model (held-out split, rows = truth):

| True \ Predicted | PASS | REWORK | SCRAP |
|---|---|---|---|
| **PASS** | 31 | 0 | 5 |
| **REWORK** | 1 | 6 | 5 |
| **SCRAP** | 3 | 0 | 9 |

**Transfer from synthetic data:** starting from our synthetic-IC model gave mask mAP50 0.414 vs 0.590 from COCO, and defect-type accuracy 37.5 % vs 70.0 %. Synthetic pre-training did **not** help here: our synthetic IC packages look very different from MVTec's through-hole transistors (different shape, background and defect types), so the broader COCO features transfer better. Pre-training on synthetic images of the *same* product as the target line would be needed for that benefit.


### 12.4 Upgrade: score fusion
In 12.3 PatchCore alone decides *defect or not*, so a defect it misses is passed even when YOLO11-seg
sees it clearly (e.g. a misplaced transistor detected with 64 % confidence). The upgraded rule flags a
part when **either** model is confident:

`defective = PatchCore score ≥ t_pc  OR  best YOLO11-seg confidence ≥ t_seg`

Both thresholds were chosen together on the **calibration split only** (best macro F1 of the
PASS / REWORK / SCRAP decision); YOLO11-seg predictions are out-of-fold, so no image is judged by a model
that saw it. The held-out split was used once, to report. 95 % confidence intervals come from
2,000 bootstrap resamples of the 60 held-out images.

| Decision rule (held-out, 95 % CI) | Accuracy | Macro F1 | Defect recall | False-reject rate |
|---|---|---|---|---|
| PatchCore decides alone (12.3) | 76.7 % (65.0 % – 86.7 %) | 0.707 (0.568 – 0.827) | 83.3 % (68.4 % – 96.2 %) | 13.9 % (3.0 % – 26.8 %) |
| **Fusion**: PatchCore ≥ 5.73 OR YOLO11-seg ≥ 0.20 | 81.7 % (71.7 % – 91.7 %) | 0.750 (0.607 – 0.877) | 87.5 % (73.7 % – 100.0 %) | 8.3 % (0.0 % – 19.4 %) |

Confusion matrix with fusion (held-out, rows = truth):

| True \ Predicted | PASS | REWORK | SCRAP |
|---|---|---|---|
| **PASS** | 33 | 0 | 3 |
| **REWORK** | 1 | 6 | 5 |
| **SCRAP** | 2 | 0 | 10 |

Fusion gets 5.0 percentage points more of the
held-out decisions right and rejects fewer good parts. The confidence intervals still overlap, so with 60 held-out
images this is a consistent improvement rather than a statistically proven one. The remaining weakness is
**bent leads**: they are flagged as defective but YOLO11-seg rarely names the type, so they get SCRAP
(unknown) instead of REWORK — the thin lead is the hardest defect to segment from 10 examples
(addressed in 12.6).

### 12.5 Uncertainty of the real-image results
Held-out PatchCore image AUROC 0.922 has a 95 % CI of
0.845 – 0.980. Every real-image number in this section comes from 100 test images (40 defective),
so differences of a few percentage points are within noise.


### 12.6 Upgrade: a dedicated defect-type classifier
Once a part is flagged, only its defect **type** is still needed, and MVTec labels are per image. Learning
to *segment* a thin bent lead from 8 examples per fold is hard; *classifying* the image is an easier
problem. Two classifiers were fine-tuned from ImageNet YOLO11s-cls (224 px, 40 epochs,
AdamW) with the **same 5 stratified folds** as 12.2, so every prediction is out-of-fold:

- **full** — the whole photo;
- **crop** — a square of 40 % of the image side centred on PatchCore's hottest
  point, so the classifier looks at the defect itself (the anomaly detector *guides* the classifier).

The detection rule is the score fusion of 12.4; the variant was chosen on the calibration split.

| Type source | Type accuracy (40 defects, OOF) | bent lead | cut lead | damaged case | misplaced | Calib. macro F1 | Held-out accuracy (95 % CI) | Held-out macro F1 |
|---|---|---|---|---|---|---|---|---|
| YOLO11-seg top detection (12.4) | 70.0 % | 30.0 % | 80.0 % | 100.0 % | 70.0 % | 0.849 | 81.7 % (71.7 % – 91.7 %) | 0.750 |
| YOLO11s-cls on the whole photo | 75.0 % | 50.0 % | 90.0 % | 80.0 % | 80.0 % | 0.849 | 81.7 % (71.7 % – 91.7 %) | 0.753 |
| **YOLO11s-cls on a PatchCore-guided crop** | 82.5 % | 60.0 % | 100.0 % | 90.0 % | 80.0 % | 0.934 | 86.7 % (76.7 % – 95.0 %) | 0.838 |

Confusion matrix with the chosen type source (held-out, rows = truth):

| True \ Predicted | PASS | REWORK | SCRAP |
|---|---|---|---|
| **PASS** | 33 | 0 | 3 |
| **REWORK** | 1 | 9 | 2 |
| **SCRAP** | 2 | 0 | 10 |

The PatchCore-guided crop raises defect-type accuracy from 70.0 % to
82.5 % and bent-lead accuracy from 30.0 % to
60.0 %; the held-out PASS / REWORK / SCRAP accuracy rises from
81.7 % to **86.7 %** (macro F1 0.750 →
0.838). Detection (defect or not) is unchanged, so the gain comes entirely from naming
the type correctly. The intervals still overlap: it is a clear but not statistically proven gain.
Caveat: the few *good* parts wrongly flagged keep their YOLO11-seg type in this evaluation (the classifier
was trained on defective images only); they are counted as errors either way. The web demo uses a final
classifier trained on all defective test images except the demo images (`models/transistor_type_cls_yolo11s.pt`).


**What this shows:** the same pipeline design (detect anomalies → identify defect type → apply rules) works
on real photographs, not only on the synthetic images. The numbers are lower than on synthetic data
because real defects are subtler and only 40 labelled defect images exist — exactly the situation a new
production line faces, which is why the label-free anomaly detector is valuable as the first stage.

## 13. Discussion

- **Detection is essentially solved** on this data (mAP50 0.995): ICs are high-contrast,
  rigid objects. The difficulty of the task lies in the *defects*.
- **Hardest / easiest defect classes:** YOLO11n-seg: hardest missing_pin (IoU 0.458), easiest contamination (IoU 0.911), U-Net: hardest missing_pin (IoU 0.092), easiest contamination (IoU 0.892).
  Thin structures (scratches, cracks: 1–3 px wide) give low IoU even when correctly found, because a
  one-pixel offset already removes a large part of the overlap — the defect-type recall in 9.4 is the
  more meaningful measure for them.
- **Why YOLO11-seg wins:** it is pretrained (COCO) and predicts *instances* with a confidence each, so a
  defect is either reported whole or not at all. The U-Net predicts every pixel independently; without
  filtering, stray pixels form small fake "cracks" and "missing pins" that scrap good devices — the
  validation-tuned size/confidence filter (Section 7.6) removes most of them, but some real small defects
  are removed with them. The U-Net was also trained from scratch on a CPU budget and was still improving
  when training stopped (Section 8), so more training would narrow the gap.
- **Decision errors** of the selected pipeline: 5 × SCRAP predicted as REWORK; 4 × REWORK predicted as PASS; 2 × SCRAP predicted as PASS; 2 × REWORK predicted as SCRAP; 1 × PASS predicted as SCRAP. Most errors occur near a rule threshold
  (e.g. a scratch of ≈ 1.5 mm or ≈ 4 mm, contamination of ≈ 0.5 mm² or ≈ 3 mm²), where a small
  measurement error flips the verdict.
- **Safety-relevant metric:** the scrap-escape rate (a SCRAP device predicted as PASS) is
  1.7 %; the false-scrap rate (good device scrapped) is 0.8 %.
  In production the rule limits can be tightened to trade more false scrap for fewer escapes.

## 14. Limitations

- The main dataset is synthetic; real-image validation (Section 12) uses only the 100 MVTec transistor test images, so its numbers have wide uncertainty. Real IC images have more varied lighting, reflections on leads, dust, real
  marking fonts and subtler defects; the models would need fine-tuning on real labelled images.
- One camera view (top). Bent leads, coplanarity and package warpage need side views or 3-D sensing.
- Measurements assume a calibrated, perpendicular camera (12 px/mm).
- CPU-only training with a limited number of epochs; a GPU would allow larger models and longer training.
- The prototype has not been validated on a real production line.

## 15. Future Work

- Collect more real defect images (MVTec has 10 per type) and fine-tune the full IC pipeline on
  images captured on the target line.
- Add bent-lead and marking-quality (OCR) checks; add side cameras.
- Learn the PASS/REWORK/SCRAP decision from operator decisions instead of fixed rules.
- Export models to ONNX/TensorRT for edge deployment at line speed; PostgreSQL for multi-line data.

## 16. Conclusion

The project delivers a complete, working computer-vision quality-control system for semiconductor
devices: data generation with exact labels, a YOLO11 detector, two compared defect segmenters,
measurement in millimetres, configurable PASS/REWORK/SCRAP rules, and a usable application layer
(CLI, camera mode, FastAPI, Streamlit, SQLite). The selected pipeline (YOLO11n + YOLO11n-seg) makes the
correct quality decision for 95.1 % of the 307 unseen test devices.
