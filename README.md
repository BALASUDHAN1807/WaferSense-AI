# AI-Based Semiconductor Wafer Defect Pattern Detection System

Classifies semiconductor **wafer maps** into 9 defect patterns using deep learning. Three models (a custom CNN, ResNet50 and EfficientNetB0) are trained on the same data and compared, and the best one is picked automatically. That model powers a command-line prediction engine and a **Gradio web app**.

> **Dataset notice:** the dataset is **synthetic**, generated by `src/dataset.py`. It is not real semiconductor-fab data, and the results describe performance on this synthetic benchmark only.

## 2. Problem statement

Chips are made on circular silicon wafers. After fabrication every die is tested, and plotting the failed dies gives a wafer map. The **spatial pattern** of failures points to the process step that went wrong. Inspecting these maps by hand is slow and inconsistent. This project treats the task as **supervised multi-class image classification**: given a wafer-map image, predict one of 8 defect patterns or *None*.

## 3. Objectives

- Validate the dataset, analyse it (EDA) and preprocess it reproducibly.
- Train a custom CNN, ResNet50 and EfficientNetB0 on the **same** train/validation/test split.
- Evaluate them with accuracy, macro and per-class precision/recall/F1, confusion matrices, training time and inference time.
- Select the best model automatically and serve it through a prediction engine and web app.

## 4. Semiconductor application

| Class | Pattern | Typical process cause |
|---|---|---|
| Center | Defect cluster in the middle | Deposition / spin-coat non-uniformity |
| Donut | Ring between centre and edge | Radial CMP or deposition non-uniformity |
| Edge-Loc | Small cluster at the edge | Handling, clamping, edge-bead removal |
| Edge-Ring | Defects around the rim | Edge etch / temperature non-uniformity |
| Loc | Small cluster inside the wafer | Local contamination |
| Near-Full | Almost the whole wafer fails | Major process excursion |
| Random | Scattered defects | Particles / contamination |
| Scratch | Thin line of defects | Mechanical scratch (robot arm, CMP debris) |
| None | No pattern | Normal wafer |

## 5. Dataset

- **900 PNG images**, 9 classes × 100, **64 × 64 grayscale**, stored in `dataset/images/<Class>/` and listed in `dataset/labels.csv` (`image,label`).
- Pixel encoding: `0` = outside the wafer, `127` = good die, `255` = defective die.
- Every image has a randomised wafer radius, defect position, size, orientation and density, plus 0–3 % random background defects. This makes the task realistic rather than trivial.
- To regenerate the dataset: `python run_project.py generate` (seed 42, so it is reproducible).

![Sample wafer maps](results/graphs/sample_wafer_maps.png)

## 6. Preprocessing

1. Convert to grayscale.
2. Resize to 64 × 64 using nearest-neighbour, so die values are not blended.
3. Divide by 255.
4. Encode labels with a fixed mapping.
5. Split 70/15/15 with stratification (seed 42) into 630 train, 135 validation and 135 test images. The split is saved to `results/reports/data_split.csv` and reused by every model.
6. Training-only augmentation: random 90° rotations and flips. These never change a wafer's defect class because the wafer is circular.

## 7. Models

| Model | Architecture |
|---|---|
| Custom CNN | 3 × (Conv2D + ReLU + MaxPool) → Flatten → Dense(128) → Dropout(0.5) → Softmax(9) |
| ResNet50 | ImageNet ResNet50 backbone → GlobalAvgPool → Dense(128) → Dropout(0.4) → Softmax(9) |
| EfficientNetB0 | ImageNet EfficientNetB0 backbone → GlobalAvgPool → Dense(128) → Dropout(0.4) → Softmax(9) |

All three models take the same 64 × 64 × 1 input. The transfer-learning models resize it to 224 × 224 × 3 *inside* the network (the `WaferToRGB` layer), so preprocessing is identical everywhere.

ImageNet weights are downloaded automatically and the backbone is frozen. If the download fails (no internet), the code falls back to a randomly initialised, trainable backbone and records this in the results (*Weights* column).

Training uses Adam, sparse categorical cross-entropy, EarlyStopping (restores the best weights), ReduceLROnPlateau and ModelCheckpoint. All settings are in `src/config.py`.

## 10. How to run

Run everything (validation, EDA, preprocessing, training all 3 models, evaluation, comparison, summary and report):

```powershell
python run_project.py all
```

Or run stage by stage:

| Command | What it does |
|---|---|
| `python run_project.py generate` | Create the synthetic dataset (already included) |
| `python run_project.py validate` | Check files, labels, duplicates, image readability |
| `python run_project.py eda` | Graphs in `results/graphs/`, `eda_summary.json` |
| `python run_project.py preprocess` | Create/verify the fixed split |
| `python run_project.py train-cnn` | Train the CNN → `models/cnn_model.keras` |
| `python run_project.py train-resnet` | Train ResNet50 → `models/resnet50_model.keras` |
| `python run_project.py train-efficientnet` | Train EfficientNetB0 → `models/efficientnetb0_model.keras` |
| `python run_project.py evaluate` | Test-set metrics, confusion matrices, reports |
| `python run_project.py compare` | `model_comparison.csv`, graphs, `best_model.json` |
| `python run_project.py predict IMAGE` | Predict one wafer image with the best model |
| `python run_project.py report` | Regenerate `report/Project_Report.md` and the README results |
| `python run_project.py test` | Run the pytest suite |
| `python run_project.py app` | Start the web app at http://127.0.0.1:7860 |

Training times on a laptop CPU: CNN ≈ 1 minute; ResNet50 and EfficientNetB0 ≈ 15–30 minutes each.

> `models/resnet50_model.keras` (~100 MB) is larger than GitHub's file limit, so it is not stored in the repo. Run `python run_project.py train-resnet` to recreate it.

## 12. Web application

`python run_project.py app` opens a Gradio page. There you can:
- upload a wafer map (or click one of the 9 examples);
- press **Predict**;
- see the class, confidence %, confidence interpretation, a probability bar for all 9 classes, and the model in use.

Invalid files, missing models and unsupported formats are reported as clear messages instead of crashes.

## 14. Limitations

- Synthetic, balanced data: real fab data is noisier, imbalanced and may contain mixed patterns.
- Small test set (15 images per class): one error changes accuracy by about 0.74 points.
- Single training run per model, CPU only.
- Classifies wafer-map patterns, not physical die images; not validated in a real fab.
